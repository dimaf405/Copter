# CUAV X7 Pro Plane：四加四倾转机架的 CyphalCAN 台架配置与测试

本文适用于本工程的 **ArduPlane/QuadPlane** 固件、八台 CyphalCAN 电调、前排四台倾转旋翼和后排四台固定旋翼。固定翼部分有左右各两个副翼舵机、左右各两片独立的 V 尾舵面，每侧两片按相同指令动作。本文给出无桨台架测试方法。电机坐标和旋向尚未核实，因此本文不提供可直接飞行的混控参数。

## 1. 已知节点与当前抓包

八台电调计划接在 X7 Pro 的 CAN2 上，目前仅连接节点 `0x10` 和 `0x11`；四个倾转舵机、四个副翼舵机和四个 V 尾舵机接在 PWM1～12 上。当前驱动以 `CAN_D2_CY_ESC_ID=16` 将八个连续节点的**反馈**归类到 `Motor1`～`Motor8`，并把这八个 Motor 输出按顺序装入两个广播油门帧。节点与油门槽是否确实一一对应，仍须逐台无桨验证：

| 实物位置 | 节点 ID | ArduPilot 功能 | 虚拟 Servo 通道 |
| --- | ---: | --- | --- |
| 左外倾转 | `0x10` | Motor1，`33` | `SERVO17` |
| 左内倾转 | `0x11` | Motor2，`34` | `SERVO18` |
| 右内倾转 | `0x12` | Motor3，`35` | `SERVO19` |
| 右外倾转 | `0x13` | Motor4，`36` | `SERVO20` |
| 左外固定旋翼 | `0x14` | Motor5，`37` | `SERVO21` |
| 左内固定旋翼 | `0x15` | Motor6，`38` | `SERVO22` |
| 右内固定旋翼 | `0x16` | Motor7，`39` | `SERVO23` |
| 右外固定旋翼 | `0x17` | Motor8，`40` | `SERVO24` |

`104.png` 截图只显示节点 `0x12`、`0x13` 的 6160、6161 和 7509 报文。两台电调反馈电频、电流、输出油门和母线电压均为零。6160 状态为 `0x0010`，表示油门丢失，当前油门源为 PWM；7509 心跳的健康值为 `0`，模式值为 `1`，表示仍处于初始化。截图没有显示 6152/6153 油门命令，也不能证明其余六台不存在。先解决供电和 CAN 油门状态，再运行电机测试。

此前在 CAN1 的两台接入抓包显示 `0x10`、`0x11` 均持续发送 7509、6160、6161，证明这两个节点能在总线上发报文；不能据此判定已经接收飞控油门。6161 报告的母线电压和输出油门均为零，6160 状态为 `0x0010`（油门丢失、油门源仍为 PWM），7509 的健康值为 `0`、模式值为 `1`（初始化）。若测试时已给电调主电源供电，应先核对供电与电调电压反馈；随后核对电调寄存器 `throtMode` 是否为 CAN 油门模式，以及飞控是否真的发出 6152/6153 零油门帧。完成这些检查之前不做电机转动测试。

## 2. 机架混控：当前编号不能直接用于飞行

八个独立安装位置应使用 QuadPlane 的 Octa 类，即 `Q_ENABLE=1`、`Q_FRAME_CLASS=3`。`Q_FRAME_CLASS=4` 是同轴八电机布局。

当前物理编号把 **Motor1～4 全部放在前排**。内置 Octa I 的前排电机却是 Motor8、4、2、6，后排是 Motor3、1、5、7，均按俯视从左到右排列。即使两排尺寸适合 Octa I，当前节点顺序也与其混控电机号不符。`Q_TILT_MASK=15` 仅表示 Motor1～4 倾转，不能修正内置混控的位置和旋向。修改 Servo Output 的通道号也不能改变当前驱动的 `MotorN` 与油门槽的对应关系。

保留现有节点编号时，需要按实测电机坐标和旋向制作自定义电机矩阵，例如使用 `Q_FRAME_CLASS=15` 的 Lua MotorsMatrix，或在固件中加入机架专用矩阵。配置好正确矩阵后，若前排四台仍为 Motor1～4，飞行倾转掩码才可使用 `Q_TILT_MASK=15`。若使用内置 Octa I，则须先让实际油门槽、物理安装位置和 Motor 编号一致；前排四台变为 Motor8、4、2、6，飞行倾转掩码应为 `170`。仅修改 `CAN_D2_CY_ESC_ID` 或 Servo Output 不能完成重排。**下文 `Q_FRAME_TYPE=15` 只供无桨逐台定位，不能直接按当前节点顺序解锁飞行。**

| 物理安装位置 | 现有节点 ID | Octa I 目标 Motor 编号 | 若节点决定槽位时的目标 ID | Octa I 目标旋向，俯视 |
| --- | ---: | ---: | ---: | --- |
| 前排左外 | `0x10` | Motor8 | `0x17` | CW |
| 前排左内 | `0x11` | Motor4 | `0x13` | CCW |
| 前排右内 | `0x12` | Motor2 | `0x11` | CW |
| 前排右外 | `0x13` | Motor6 | `0x15` | CCW |
| 后排左外 | `0x14` | Motor3 | `0x12` | CCW |
| 后排左内 | `0x15` | Motor1 | `0x10` | CW |
| 后排右内 | `0x16` | Motor5 | `0x14` | CCW |
| 后排右外 | `0x17` | Motor7 | `0x16` | CW |

此表的 Motor 编号和旋向来自当前代码的 Octa I 矩阵。目标 ID 列**仅在实测证实“节点 `0x10～0x17` 分别消费第 1～8 油门槽”且改节点号会同步改变所选槽位时成立**。厂家协议没有给出完整的 Node-ID 与油门槽对应公式。改电调节点 ID 是否同时改变选槽行为，必须逐台实测，不能直接假定。

完成混控还需要八台电机相对重心的前后、左右坐标，各电机从机顶俯视的 CW/CCW 旋向，各电机实际推力，以及倾转轴和舵机行程。不能只凭“4+4 两排”推定这些量。

## 3. Mission Planner 的 Servo Output

先备份完整参数。刷入本工程针对 CUAV-X7 编译的 `build/CUAV-X7/bin/arduplane.apj`；确认连接后车辆类型是 Plane，且完整参数表中出现 `CAN_D2_CY_*`。在 **SETUP → Mandatory Hardware → Servo Output** 设置实体 PWM 的功能；`SERVO17`～`SERVO24` 等虚拟通道建议在 **CONFIG → Full Parameter Tree/List** 设置。参数保存后按下述顺序重启。

1. 设 `Q_ENABLE=1`，保存并重启；设 `SERVO_32_ENABLE=1`，保存并重启。先确认完整参数表确实出现 `SERVO17_FUNCTION`～`SERVO24_FUNCTION`。
2. 依次设 `SERVO17_FUNCTION=33` 至 `SERVO24_FUNCTION=40`，每个 Motor 功能一个虚拟通道。确认参数已保存。
3. 检查实体 PWM1～14。QuadPlane 默认可能把 Motor1～8 放在 PWM5～12；将实体通道中重复的 Motor 功能改为下表的舵机功能或 `Disabled(0)`，再重启。八台 CAN 电调的 PWM 油门线不要接到飞控 PWM 输出。

下表是**接线示例**，以实际插口为准。X7 Pro 板级定义有 14 路实体 PWM；`SERVO17`～`SERVO24` 没有对应实体插口，仅为 CAN 驱动提供内部 Motor 输出。

| 实体 PWM | 接线示例 | `SERVOn_FUNCTION` |
| --- | --- | ---: |
| 1～4 | 前排四个同步倾转舵机，依次左外、左内、右内、右外 | 各 `41`，TiltMotorsFront |
| 5、6 | 右侧两块独立副翼舵面 | 各 `4`，Aileron |
| 7、8 | 左侧两块独立副翼舵面 | 各 `4`，Aileron |
| 9、10 | 左侧两块独立 V 尾舵面 | 各 `79`，VTailLeft |
| 11、12 | 右侧两块独立 V 尾舵面 | 各 `80`，VTailRight |
| 13、14 | 备用，未接设备时 | `0`，Disabled |

四片副翼都是普通副翼，故都用功能 `4`；同一功能会给出同一副翼控制量，每路可用 `SERVOn_REVERSED`、`MIN`、`TRIM`、`MAX` 独立设方向、中立和行程。左右副翼需要相反的实际舵面运动，逐路核对后设置反向；若以后要让副翼兼作襟翼，才考虑不同的 FlaperonLeft/Right 功能 `24`/`25`。V 尾四片虽各由独立舵机驱动，同侧两片需要同一指令，故分别重复使用 `79` 或 `80`。Plane 会在内部将俯仰和偏航混合为 V 尾输出，不需要分配实体 `Elevator(19)` 或 `Rudder(21)`。遥控器本身的 V 尾混控应关闭。先按舵机允许的行程限制端点，再分别核对四片 V 尾及四片副翼的中立和方向。倾转功能 `41` 用 `MIN`、`MAX`、`REVERSED` 确定竖直与前推位置，`TRIM` 不控制中间倾转角。`MIXING_GAIN` 默认为 `0.5`，`MIXING_OFFSET` 默认为 `0`，先保持默认值做台架检查。

实体 PWM1～12 都是普通舵机时，设置 `SERVO_RATE=50` Hz，即每 `20 ms` 发一次脉冲；这是 PWM 刷新频率，不是脉宽。当前代码中每路 `SERVOn_MIN=1100` µs、`TRIM=1500` µs、`MAX=1900` µs 是默认值，不应未经机构检查就扩大行程。X7 Pro 的 PWM1～4、5～8、9～12 分别共用三个硬件定时器组，同组不能设置不同频率。只有舵机厂家明确支持更高刷新率，且同组全部舵机兼容时才考虑升频。`CAN_D2_CY_ESC_RT=200` Hz 仅为 CAN 油门帧速率，不改变舵机 PWM 频率。八台电调不接飞控 PWM 油门线，`Q_M_PWM_TYPE` 保持普通输出类型 `0`；默认 `Q_M_PWM_MIN/MAX=1000/2000` 仍参与驱动内部的油门量换算，不是 X7 上的电机 PWM 信号。

若舵机确实满足 `500/1500/2500 µs = -100°/0°/+100°` 的线性关系，`1100/1500/1900 µs` 对应舵机输出轴约 `-40°/0°/+40°`；`1000/2000 µs` 对应约 `±50°`，`800/2200 µs` 对应约 `±70°`。这只是舵机轴角度，不是倾转电机或舵面的最终角度；连杆几何会改变实际转角。当前固件的 `SERVOn_MIN/TRIM/MAX` 参数标注范围为 `800～2200 µs`，因此不能把 `500/2500 µs` 直接作为这份固件的推荐端点。先用 `1100/1500/1900 µs` 做无桨检查，再根据实际竖直/水平倾转位置、舵面偏角和机械限位逐路调整。若倾转机构需要舵机轴走完整 `90°`，在机构中位对应 `1500 µs` 且连杆允许时，理论端点可从 `1050/1950 µs` 附近测起；不能仅凭舵机标称 `±100°` 推定所需端点。

`SERVO1～4_FUNCTION=41` 的连续倾转输出把 `MIN`、`MAX` 分别作为两个端点，`TRIM` 不决定中间角。`SERVO5～12` 的副翼和 V 尾功能以 `TRIM` 为中立点，正负控制量分别向 `MAX`、`MIN` 变化。每路用 `SERVOn_REVERSED=0/1` 单独核对实际运动方向。对于两块独立舵面使用相同功能的情况，也要分别调整中立、反向和行程；各侧舵面所需偏角由机体气动和机构决定，不应统一扩大到舵机的机械极限。

四个前排舵机若要左右差动实现矢量偏航，不应采用上表四路都为 `41` 的同步方案。此时须核实机构后再配置 `Q_TILT_TYPE=2` 与左右倾转功能 `75`/`76`；该类型会改变悬停偏航控制，不能只为实现“四台可倾转”而启用。普通同步连续倾转使用 `Q_TILT_TYPE=0`。

若没有独立的固定翼前推电机，不要把某个实体 PWM 口保留为 `Throttle(70)`。Plane 的倾转代码会把固定翼油门分配给 `Q_TILT_MASK` 中的电机。按当前待验证的油门槽顺序，前排暂为 Motor1～4；若最终使用内置 Octa I，前排则必须对应 Motor8、4、2、6。

当前倾转代码在纯固定翼模式下以 `Q_TILT_MASK` 选择前推电机；后排四台竖直电机不承担前推油门。它们在垂起、过渡和启用垂起辅助时的动作仍须另行核对。若设计要求后排在固定翼巡航时继续提供推力，需要重新确认推进布局与控制策略。

## 4. CAN 接收与无桨电机测试

**全程拆下八副螺旋桨，固定机体，准备能独立切断电调主电源的开关。** 不要关闭 `ARMING_CHECK`。Motor Test 的检查比正常解锁少，电机测试成功不能代替整机预解锁检查。

### 阶段 A：只收报文

CAN2 专用于这套 CyphalCAN 电调。若 CAN1 仍连接 DroneCAN 设备，保留 `CAN_P1_DRIVER=1`、`CAN_D1_PROTOCOL=1` 和原总线速率；若 CAN1 完全不用，可设 `CAN_P1_DRIVER=0`。不要把两种协议放进同一 CAN 驱动。X7 Pro 板级定义中 CAN2 与高速 USB 共用资源；使用 CAN2 时保持默认的全速 USB 配置。设置以下参数并重启：

```text
CAN_P2_DRIVER      2
CAN_P2_BITRATE     500000
CAN_D2_PROTOCOL    15
CAN_D2_CY_NODE     10
CAN_D2_CY_ESC_ID   16
CAN_D2_CY_ESC_RT   200
CAN_D2_CY_ESC_BM   0
CAN_D2_CY_POLES    0
CAN_P2_OPTIONS     1
LOG_DISARMED       1
```

在独立 CAN 分析仪或飞控 DataFlash 的 `CANF` 日志中，逐台确认 7509 心跳、6160/6161 反馈和节点 ID。`ESC_BM=0` 时驱动不会发送油门帧，而且预解锁检查会报告 `invalid ESC channel mask`；这是只接收报文阶段的预期结果，不要为了消除该提示而关闭 `ARMING_CHECK`。在此阶段看到电调报告油门丢失，也不等于已验证 CAN 油门模式。若 6161 报告母线电压 `0.0 V`，检查电调主电源及其反馈定义。`CAN_P2_OPTIONS` 的最低位 `1` 会记录全部 CAN 帧；若原值已有其他位，应保留其他位并勾选此位，测试后可恢复原值。

抓包工具设置为 `500 kbit/s`、29 位扩展帧。对每个 `N=0x10～0x17`，应持续看到心跳 `0x107D55NN`、6160 反馈 `0x147810NN`、6161 反馈 `0x147811NN`；这里末尾 `NN` 是两位十六进制节点号，例如 `0x12` 对应 `0x107D5512`、`0x14781012`、`0x14781112`。心跳约每秒一次，6160/6161 默认约每 25/50 ms 一次。记录八个节点的最后接收时间、心跳健康值与模式、6160 状态和电流、6161 油门和母线电压。只见心跳表示节点出现在总线上，不能证明两类反馈都可用；若三类帧均无，先检查供电、终端电阻、线序和速率。Mission Planner 可在 **Flight Data → DataFlash Logs → Download DataFlash Log Via Mavlink / Review a Log** 下载并查看 `CANF`；ArduPilot 日志的 `CANF.Id` 还包含扩展帧标志，比较 29 位 CAN-ID 时先取 `Id & 0x1FFFFFFF`。若本机日志查看器不能直接解码数据字段，可导出帧或使用独立 CAN 分析仪。

协议第 7 页规定：6152 广播第 1～4 轴油门，6153 广播第 5～8 轴油门，两帧都没有“目标电调 Node-ID”字段。默认 `CAN_D2_CY_NODE=10` 时，飞控发送帧的原始 29 位 CAN-ID 分别为 `0x0C78080A`、`0x0C78090A`，末尾 `0x0A` 是飞控自己的源 Node-ID。`CAN_D2_CY_ESC_ID` 只改变驱动接收反馈时的索引基准，**不能改变这两个发送帧的 CAN-ID、油门槽顺序或电调自身的 Node-ID**。本驱动未实现协议 6145 的电调改号命令。若确需修改电调真实地址，应使用厂家流程，且每次只连接或上电一台，以免广播改号影响全部电调。

### 阶段 B：只测试一台

为启用 Mission Planner 电机测试，先设 `Q_ENABLE=1`、`Q_FRAME_CLASS=3`、`Q_FRAME_TYPE=15`。这里的 Octa I **只用于无桨台架定位**，现有油门槽与物理位置尚未按 Octa I 重排。电机测试阶段可设 `Q_TILT_ENABLE=0`、`Q_TILT_MASK=0`，不测试倾转机构。确认八个虚拟 Motor 功能已设置。

只接节点 `0x10`、`0x11` 时，仍建议设置 `SERVO_32_ENABLE=1` 并重启，再将 `SERVO17_FUNCTION`～`SERVO24_FUNCTION` 依次设为 `33`～`40`。其中 `SERVO17_FUNCTION=33` 是 Motor1，`SERVO18_FUNCTION=34` 是 Motor2；实体 PWM 口不能再重复分配这些 Motor 功能。日志中的 `Motors: no SERVOx_FUNCTION set to Motor1` 和 `CyphalCAN: motor 1 function missing` 均指向缺失的 Motor1 功能，不能通过更改节点 ID 消除。

两台电机逐台测时，先设 `CAN_D2_CY_ESC_BM=1` 并重启，确认飞控持续发送 6152/6153 零油门帧、节点 `0x10` 的 6160 油门源变为 CAN、油门丢失位清零、6161 报告合理的母线电压和零输出、7509 模式进入操作模式。满足这些条件后，在 Mission Planner 的 Motor Test 里用临时 Octa I 的 **E** 按钮，以低油门、短时间检查 Motor1；记录真正转动的节点和位置。随后断开电调主电源，改 `ESC_BM=2` 并重启，重复状态检查，用 **A** 按钮测 Motor2；预期为节点 `0x11`，但须以实际结果为准。`ESC_BM=3` 会同时启用两槽，仅在前两个单槽均已核对后做全机无桨检查。电机测试代码要求 QuadPlane 机架已初始化、测试前未解锁、安全开关已释放且急停未激活；其检查不要求其余六台电调已接入，因此可单独测试这两台，正常整机解锁检查仍会因其他条件失败，不能以电机测试结果代替。

若要检查 Motor3 油门槽，设 `CAN_D2_CY_ESC_BM=4`，保存并重启；按现有编号预期节点 `0x12` 响应。Motor4 油门槽则设 `CAN_D2_CY_ESC_BM=8`，预期节点 `0x13` 响应。协议未给出 Node-ID 与槽位的完整对应公式，实际响应必须无桨测出。该掩码不是目标 Node-ID 选择器或急停开关。驱动仍会广播两组油门帧，未选槽填零。改动掩码后必须重启。

先观察飞控发出的 6152/6153 油门帧，未解锁时应为零油门。再核对所选电调：6160 的油门源位 `bit3=1`、油门丢失位 `bit4=0`，7509 模式为 `0`，6161 油门为零且主电源电压符合实物。状态仍与截图相同则先排查供电、CAN 油门配置和命令接收，不继续电机转动测试。

在 **SETUP → Optional Hardware → Motor Test**，释放飞控安全开关，确认未启用急停。先选低油门，例如 `5%`、`1 s`；一次只测试一个按钮，等电机完全停下后再测下一个。若电机不转，先查看状态及 CAN 命令，确认无误后才小幅提高油门。首次验证可只给一台电调接主电，但要保留 CAN 总线两端的正确终端电阻。任一电机异常，立即切断电调主电源。

在上述**临时 Octa I** 配置中，按钮按代码中 `_test_order` 选择 Motor。表内节点和物理位置以“第 N 槽响应节点 `0x10+N-1`”为待验证假设，**不是已证实的飞行映射**。

| --- | --- | ---: | ---: | --- |
| A | Motor2 | `2` | `0x11` | 左内倾转 |
| B | Motor6 | `32` | `0x15` | 左内固定旋翼 |
| C | Motor7 | `64` | `0x16` | 右内固定旋翼 |
| D | Motor5 | `16` | `0x14` | 左外固定旋翼 |

### 阶段 C：全机台架检查

逐台节点和接线确认后，可设 `CAN_D2_CY_ESC_BM=255` 并重启，在**无桨状态**逐个测试 A～H。记录每个按钮实际对应的节点、物理位置和电机旋向；这一步不需要预先知道精确臂长。正常解锁前，每台电调都须持续发送 6160、6161、7509；报告 CAN 油门源、零输出、运行模式和无故障。检查安全开关、急停、上锁以及 CAN 命令中断时电调自身的停机行为。本驱动发送零油门不能代替电调在物理 CAN 断线后的内部失联保护。

## 5. 这些参数分别做什么

以下是 CAN2 接八台电调、PWM1～12 接十二个舵机时的**无桨台架起始值**。先备份参数，按第 3 节设置输出，再按第 4 节分阶段启用油门槽。`CAN_D2_PROTOCOL=15` 和 `CAN_D2_CY_*` 只存在于含本工程驱动的固件中。不要把此表当作飞行参数文件；其中 Octa I 的电机位置与当前物理编号尚未匹配。

| 参数 | 本机台架值或阶段 | 作用 |
| --- | --- | --- |
| `Q_ENABLE` | `1` | 启用 Plane 的 QuadPlane 垂起电机和相关参数。 |
| `Q_FRAME_CLASS` | 临时 `3` | 指定八个独立旋翼的 Octa 类；`4` 表示四组同轴八电机。最终若采用 Lua 电机矩阵，可使用 `15`。 |
| `Q_FRAME_TYPE` | 临时 `15` | 指定内置 Octa I 的混控和 Motor Test 按钮顺序；当前实物编号与其混控不符，因此仅用于无桨定位。 |
| `Q_TILT_ENABLE`、`Q_TILT_MASK` | 电机定位时 `0`、`0` | 临时不执行倾转控制。若飞行时使用内置 Octa I 且映射正确，前排 Motor8、4、2、6 对应掩码 `170`；若用自定义矩阵保留前排 Motor1～4，则对应 `15`。掩码表示 Motor 编号，不是舵机通道号。 |
| `SERVO_RATE` | `50` Hz | 实体 PWM 舵机的默认刷新频率。X7 Pro 同一硬件定时器组共用频率；与 CAN 油门频率无关。 |
| `Q_TILT_TYPE` | 同步连续倾转用 `0` | `2` 是左右差动矢量偏航，不是“四台可倾转”的通用开关。 |
| `SERVO_32_ENABLE` | `1` | 显示并启用 `SERVO17`～`SERVO24` 参数；这些通道在 X7 Pro 上用于内部 CAN Motor 功能，不对应实体 PWM 插口。 |
| `SERVO1～4_FUNCTION` | 每路 `41` | 四路连续倾转舵机使用相同倾转指令，分别调整端点和反向。 |
| `SERVO5～8_FUNCTION` | 每路 `4` | 右侧两片、左侧两片副翼使用普通 Aileron 功能；每路独立调整方向、中立与行程。 |
| `SERVO9～10_FUNCTION` | 每路 `79` | 左侧两片独立 V 尾舵面使用相同的左 V 尾混合指令。 |
| `SERVO11～12_FUNCTION` | 每路 `80` | 右侧两片独立 V 尾舵面使用相同的右 V 尾混合指令。 |
| `SERVO13～14_FUNCTION` | 未使用时每路 `0` | 清除 X7 Pro 上未接线实体 PWM 输出的旧电机功能。 |
| `SERVO1～12_MIN/TRIM/MAX` | 起始为每路 `1100/1500/1900` µs | 对标称 `500/1500/2500 µs = -100°/0°/+100°` 的舵机，约为轴角 `-40°/0°/+40°`。实测后逐路调整；倾转功能忽略 `TRIM`。 |
| `SERVO1～12_REVERSED` | 先保持原值，逐路测方向后设 `0` 或 `1` | 单独反转每片舵面的运动方向；左右副翼和 V 尾不能仅靠统一数值推定方向。 |
| `SERVO17～24_FUNCTION` | `33～40` | 将 QuadPlane Motor1～8 分配给虚拟通道，供当前 CAN 驱动读取。 |
| `Q_M_PWM_TYPE`、`Q_M_PWM_MIN/MAX` | `0`、`1000/2000` | CAN 电调虽无 PWM 油门线，当前驱动仍依据内部电机 PWM 标度换算广播油门值。 |
| `CAN_P2_DRIVER` | `2` | 将物理 CAN2 分配给第二个 CAN 协议驱动。 |
| `CAN_P2_BITRATE` | `500000` | 设置物理 CAN2 总线速率为 500 kbit/s，须与电调一致。 |
| `CAN_D2_PROTOCOL` | `15` | 让第二个 CAN 协议驱动运行本工程的 CyphalCAN 电调协议。 |
| `CAN_D2_CY_NODE` | `10`，十进制 | 飞控自身的发送源 Node-ID；不是任何电调的目标地址。协议要求广播油门发送源为 0～15、126 或 127。 |
| `CAN_D2_CY_ESC_ID` | `16`，即 `0x10` | 接收反馈时，把哪个电调源 Node-ID 当作 Motor1；**不重定向油门广播，也不更改电调地址**。现有八节点建议保持 `16`。 |
| `CAN_D2_CY_ESC_RT` | 默认 `200` Hz | 两组油门广播帧的发送频率；不是电机转速。 |
| `CAN_D2_CY_ESC_BM` | `0`、单槽位或 `255` | 决定哪些 Motor 油门槽填入输出；`0` 时不发油门帧，`255` 选择八槽。改后重启，不能当急停开关。 |
| `CAN_D2_CY_POLES` | 未知磁极对数时 `0` | 设为 `0` 时不把电频换算成机械 RPM；有准确磁极对数后再填。 |
| `CAN_P2_OPTIONS`、`LOG_DISARMED` | 记录报文时最低位 `1`、`1` | 记录 CAN2 全帧及未解锁日志，供核对节点、油门帧和反馈；测试后可恢复原值。 |
| `MIXING_GAIN`、`MIXING_OFFSET` | 先保持 `0.5`、`0` | Plane 内部 V 尾俯仰/偏航混合的增益与相对权重；先验证舵面方向与行程，再决定是否调整。 |

`CAN_D2_CY_ESC_BM` 分三步使用：`0` 用于只接收报文和舵机检查；单槽位 `1/2/4/8/16/32/64/128` 用于逐台无桨电机测试；`255` 只在八台实际槽位和状态均确认后用于全机无桨检查。`CAN_P2_DRIVER`、`CAN_D2_PROTOCOL`、`CAN_D2_CY_ESC_BM` 等注明重启的参数，保存后重启再判断结果。CAN1 若接 DroneCAN 设备，应保留其独立驱动配置；CAN2 独立运行本工程协议。不要把两种协议放到同一物理总线上。

## 6. 倾转舵机和固定翼舵面

测试倾转舵机的机械行程**不需要等待电机尺寸和旋向数据**。先拆桨、保持飞控未解锁、设 `CAN_D2_CY_ESC_BM=0` 并重启，确保飞控不发送电机油门帧。然后可临时设 `Q_TILT_ENABLE=1`、`Q_TILT_MASK=15`、同步连续机构的 `Q_TILT_TYPE=0`，保存并重启。这个 `15` 仅依当前前排占用 Motor1～4 槽位作无桨舵机台架检查。在 `MANUAL` 模式检查前排旋翼朝前，在 `QSTABILIZE` 模式检查朝上；按实际机构调整四个倾转通道的反向和行程。倾转机构卡阻或任一电机朝向不一致时停止。电机测试阶段再按第 4 节设 `Q_TILT_ENABLE=0`、`Q_TILT_MASK=0`，保存并重启。内置 Octa I 飞行映射完成后，四台前排电机的掩码应为 `170`。

固定翼舵面在 `MANUAL` 模式检查遥控器对应关系，在 `FBWA` 模式检查飞控姿态改变后的纠偏方向。先核对机头方向、飞控安装方向和遥控器通道，再调整单个舵机的反向。测量 PWM1～12 的频率应为 `50` Hz，检查舵机供电电压、静止位置及满行程时有无卡阻。Mission Planner 的 `DO_SET_SERVO` 不能替代已分配 Motor 或倾转功能的电机测试。

按接线逐路记录实物舵机的 PWM 口、舵面位置、中立脉宽、两个端点脉宽、实际运动方向和是否卡阻。保持飞控未解锁且电机油门广播关闭，给舵机总线供电，并释放飞控安全开关以允许 PWM 输出。先在 Mission Planner 的 **SETUP → Mandatory Hardware → Servo Output** 核对 PWM1～12 的功能，并在 **Flight Data → Status** 观察可用的舵机输出值；软件数值只能证明飞控计算了输出，还要用 PWM 测量工具确认实际插口，或断电后只接一台舵机再上电核对。在 `MANUAL` 模式小幅操作横滚，检查 PWM5～8 四片副翼是否产生正确的左右差动；小幅操作俯仰和偏航，分别检查 PWM9～12 四片 V 尾的混合方向。同侧两片独立舵面应同指令运动，但每片都必须分别检查。最后在 `FBWA` 模式轻微改变机体姿态，确认舵面产生纠偏动作。倾转舵机按本节前述模式切换分别检查 PWM1～4 的竖直和朝前端点。任何一片方向相反时只修改该路 `SERVOn_REVERSED`，然后重复全部相关动作检查。

在取得八台电机坐标、旋向、后排旋翼在固定翼阶段的运行要求，并确认四个倾转舵机是否同步前，不要把台架临时机架参数用作飞行配置。上述缺失数据不妨碍无桨逐台电机测试和 V 尾、副翼的地面动作检查。

## 7. 飞行控制环的调参顺序

完成油门槽与实际电机位置映射、旋向、倾转掩码、推力方向和失联保护的无桨验证后，再依据机体实际质量、重心、臂长、桨和电调响应制订飞行测试。仅填入 Octa I 参数、通过 Motor Test 或通过预解锁检查，都不能证明该机能够正常飞行。

1. 先确认遥控器映射、姿态传感器方向、电池与空速计、四片副翼和四片 V 尾的操纵及纠偏方向、倾转端点和同步性。默认 `SERVO_RATE=50` Hz；按舵机厂商额定范围确定每路 `MIN/TRIM/MAX`。测试所有电调的上锁、急停及 CAN 断线保护。
2. 有桨飞行前测定各轴推力方向、悬停油门裕度、油门死区和振动。依据实际数据处理 `Q_M_SPIN_ARM`、`Q_M_SPIN_MIN`、`Q_M_THST_EXPO`、`Q_M_THST_HOVER`，不要直接复制其他机型的数值。验证八台电机在所需油门下不饱和且温度、电流合理。
3. 在受控场地完成初始悬停后，先调垂起角速度内环 `Q_A_RAT_RLL_*`、`Q_A_RAT_PIT_*`、`Q_A_RAT_YAW_*`，对照日志的目标与实际角速度、输出饱和和振动；再调姿态角外环 `Q_A_ANG_RLL_P`、`Q_A_ANG_PIT_P`、`Q_A_ANG_YAW_P`。这一步以前不能靠加大增益掩盖电机位置、旋向或传感器方向错误。
4. 垂起姿态稳定后，再核对 `QHOVER` 的高度、垂直速度和加速度环，主要是 `Q_P_D_POS_P`、`Q_P_D_VEL_P`、`Q_P_D_ACC_*`；随后检查 `QLOITER` 的水平位置与速度环 `Q_P_NE_*`。先确认高度传感器、GPS 和罗盘质量。
5. 固定翼部分先用受控飞行与日志调 `RLL_RATE_*`、`PTCH_RATE_*` 和姿态角响应，再调空速与 `TECS_*` 高度/速度控制，最后调 `NAVL1_*` 路径跟踪。转换阶段在垂起和固定翼控制都可用以后再调整 `Q_TILT_RATE_UP/DN`、`Q_TILT_MAX`、空速门槛及转换超时。每次改一类参数，并保存改前值与日志。

本工程 CUAV-X7 的 `QAUTOTUNE` 默认仅在 SITL 启用；飞行硬件若可见 `QWIK_*`，完成稳定初始悬停和振动检查后可按 ArduPilot 的 VTOL QUICKTUNE 流程微调内环。其基本入口是 `QWIK_ENABLE=1`，并给一个空闲遥控通道设置 `RCx_OPTION=181`；详细开关动作、取消和保存方法应按该功能文档执行。不要在当前电机映射未解决时使用自动调参。具体步骤参见 [QuadPlane 垂起调参](https://ardupilot.org/plane/docs/quadplane-vtol-tuning-process.html)、[VTOL QUICKTUNE](https://ardupilot.org/plane/docs/quicktune.html)、[Plane AUTOTUNE](https://ardupilot.org/plane/docs/automatic-tuning-with-autotune.html) 与 [TECS 调参](https://ardupilot.org/plane/docs/tecs-total-energy-control-system-for-speed-height-tuning-guide.html)。

## 8. 当前仅接两台 CAN2 电调时的排查

先拆下全部螺旋桨，固定机体，准备能立即切断电调主电源的开关。保存参数备份。在 Mission Planner 完整参数表中设 `CAN_P2_DRIVER=2`、`CAN_P2_BITRATE=500000`、`CAN_D2_PROTOCOL=15`，保存并重启。若 CAN1 仍用于 DroneCAN，保留其原有 `CAN_P1_DRIVER=1`、`CAN_D1_PROTOCOL=1` 和位速率；若 CAN1 空置且仍配置为 CyphalCAN，停用该旧驱动。重启后确认 `CAN_D2_CY_*` 已出现，再设 `CAN_D2_CY_NODE=10`、`CAN_D2_CY_ESC_ID=16`、`CAN_D2_CY_ESC_RT=200`、`CAN_D2_CY_ESC_BM=0`、`CAN_D2_CY_POLES=0`、`CAN_P2_OPTIONS=1`、`LOG_DISARMED=1`，保存并再次重启。`CAN_P2_OPTIONS` 原有其他位应保留。

先保持 `ESC_BM=0`：在 **CAN2** 抓取 `0x107D5510/11`、`0x14781010/11`、`0x14781110/11`，或查看 DataFlash `CANF`。此前在 CAN1 上看到的帧不能证明 CAN2 线路或飞控接收正常。`ESC_BM=0` 不发送油门，因此此阶段只证明接收通路。若完全无帧，核对真实 CAN2 插口、CAN-H/CAN-L、终端电阻、500 kbit/s、电调供电，以及是否启用了与 CAN2 冲突的高速 USB。

随后只测一槽。检查 `SERVO17_FUNCTION=33`、`SERVO18_FUNCTION=34`，且实体 PWM1～14 不重复分配 Motor1/2；保持 `Q_ENABLE=1`、临时 `Q_FRAME_CLASS=3`、`Q_FRAME_TYPE=15`、`Q_TILT_ENABLE=0`。设 `CAN_D2_CY_ESC_BM=1` 并重启，确认飞控在 CAN2 发 `0x0C78080A` 和 `0x0C78090A` 两组零油门帧。前者承载 Motor1～4 的油门槽。确认节点 `0x10` 的 6160 报告 CAN 油门源且没有油门丢失、6161 母线电压符合实物、7509 心跳处于正常运行模式。释放硬件安全开关、确认急停未激活、保持飞控未解锁；Mission Planner 的 Motor Test 设 `5%`、`1 s`、一次，仅按临时 Octa I 的 **E** 按钮。记录实际转动节点及其反馈。完全停转并切断电调主电源后，改 `ESC_BM=2`、重启，重复状态检查，按 **A** 按钮测 Motor2，预期节点 `0x11` 响应，但以实测为准。两槽都确认后才设 `ESC_BM=3` 做两台无桨复测。只接两台时不要设 `255` 做正常解锁。

若所有 PWM1～12 舵机都不动，优先检查日志中的 `Hardware safety switch`：这表示安全状态尚未释放，底层可把物理 PWM 脉冲置零。先令 `CAN_D2_CY_ESC_BM=0` 并重启，拆桨，保持飞控未解锁；按机身安全按钮，确认安全状态解除，再测试舵机。不要通过关闭 `ARMING_CHECK` 或全局禁用安全开关来代替这一步。检查舵机电源轨是否有符合舵机要求的独立供电，并用万用表核对 PWM 插口的电源脚与地脚；USB 给飞控供电不能证明舵机电源轨有电。

在 Mission Planner 的 **Flight Data → Status** 查看 `servo1_raw` 等输出值，同时用 PWM 测量工具测实际插口的脉宽和 50 Hz 刷新率。若软件数值变化而物理插口无脉冲，继续查安全状态、`SERVO_GPIO_MASK` 是否把这些通道设为 GPIO、PWM 插口接线及板级输出；若插口有脉冲而舵机不动，查舵机电源轨、地线、插头方向和舵机本体。若软件数值不变，切到 `MANUAL`，确认遥控器输入在变化，并核对 PWM5～8 为功能 `4`、PWM9～10 为 `79`、PWM11～12 为 `80`。PWM1～4 为倾转功能 `41`，其测试还需按第 6 节配置倾转功能和飞行模式。可临时用未接设备的 PWM13 做独立隔离测试：设 `SERVO13_FUNCTION=0`，释放安全开关，再向通道 13 发送 `MAV_CMD_DO_SET_SERVO` 的 `1500 µs` 和 `1600 µs`；该命令不用于已分配功能的 PWM1～12。

日志中的 `RTL mode not armable` 表示当前 RTL 模式不能解锁，地面操纵检查改用 `MANUAL`；`GPS 1: Bad fix`、`Compass not calibrated`、`3D Accel calibration needed`、`Q_ASSIST_SPEED is not set` 是各自独立的飞行预解锁条件。它们不能单独解释十二路实体 PWM 全无脉冲。无桨 Motor Test 的检查比正常解锁少；通过 Motor Test 不能替代解决这些预解锁问题，也不能证明当前电机排列可飞行。
